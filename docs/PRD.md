## 2. 产品定位与目标

### 2.1 一句话定位

TMP 是面向企业 DBA 的 TiDB 多集群统一纳管与图形化管控平台——**不做集群变更，只做看得清、管得住、查得到**：把散落在多套 TiUP 环境里的 TiDB 集群收敛到一个控制台，提供统一视图、统一巡检、统一用户与主机视角。

### 2.2 产品目标

| # | 目标 | 可衡量标准 |
| --- | --- | --- |
| G1 | 多集群统一纳管，一个控制台看清全部集群 | 单实例可纳管 ≥ 20 套 TiDB 集群；总览页 3 秒内给出全局健康结论 |
| G2 | 全生命周期信息可见，降低跨系统跳转成本 | 集群基础信息、拓扑、实例、用户、主机、巡检结论在同一集群视角内闭环；从任意页面到目标集群 ≤ 2 次点击 |
| G3 | 巡检补足监控盲区，让安全隐患可交付 | 内置 ≥ 20 条巡检项；单集群巡检报告可一键导出 Markdown/HTML |
| G4 | TiDB 特性管理专业化，覆盖 v6.5~v8.5 差异 | 版本能力矩阵驱动 UI 显隐（如 Resource Group 仅 v7.5+ 可见）；不支持的版本给出明确提示而非报错 |
| G5 | 开箱即用，零依赖演示 | 无真实集群时，开启演示模式可完整走通全部 P0 流程 |

### 2.3 明确的非目标（Negative Scope）

以下能力**本期不做**，明确归属 TiUP 或后续版本：

| 不做的事 | 归属 | 说明 |
| --- | --- | --- |
| TiDB 集群安装、部署、初始化 | TiUP | TMP 只纳管已存在的集群 |
| 扩缩容（Scale-out / Scale-in） | TiUP | TMP 不做节点增删 |
| 集群重启、停机、升级、迁移 | TiUP | TMP 不发起任何集群生命周期变更 |
| 备份恢复、数据同步链路管理 | TiDB 生态工具（BR / TiCDC 独立运维） | 仅展示 TiCDC 组件状态，不编排 |
| SQL 开发 IDE、SQL 审核与上线 | 独立产品 | 仅提供慢查询只读查看 |
| 告警引擎自建 | Prometheus / Grafana | TMP 消费已有监控地址，不自建告警 |
| 多租户隔离与计费 | 后续版本 | 本文为单租户形态 |

### 2.4 产品功能架构（补充原文「待补充」部分）

从产品视角自上而下分四层，**只描述功能域，不涉及技术选型**：

| 层次 | 功能域 | 包含模块 | 面向对象 |
| --- | --- | --- | --- |
| L1 接入层 | 统一入口与身份 | 登录认证、平台用户与角色、权限控制、审计 | 平台自身 |
| L2 管控层 | 业务功能域 | 总览大盘、集群管理、主机管理、TiDB 对象管理（用户/会话/参数/性能）、巡检 | TiDB 集群及资源 |
| L3 采集层 | 数据获取与归一 | 采集适配（SSH / MySQL 协议 / PD API）、采集调度、快照与降级、mock 数据源 | 被纳管环境 |
| L4 支撑层 | 公共能力 | 任务中心（异步编排与可视）、凭据管理、系统设置、任务跳转总线 | 全平台 |

**核心设计原则**

1. **对象化**：以「集群」为聚合根，实例、TiDB 用户、会话、巡检报告均挂在集群下；主机额外提供跨集群全局视图。
2. **单集群沉浸式**：进入某集群后左侧导航切换为集群内视图（概览/拓扑/实例/用户/会话/参数/性能/巡检/变更），退出回全局视图。对标 OceanBase OCP 控制台交互。
3. **Job 串联**：所有耗时操作（接管采集、连接测试、巡检、Kill 会话、改参数）均产出「任务」，以步骤流程图 + 日志呈现，任意页面可经顶栏跳转。
4. **读优先、写克制**：写操作（改参数、删用户、Kill 会话）一律二次确认 + 审计，且不触碰集群拓扑。

## 3. 用户角色与典型场景

| 角色 | 画像 | 权限定位 |
| --- | --- | --- |
| 平台管理员（admin） | DBA 团队负责人 / 基础设施负责人 | 全平台配置、用户与角色、凭据、接管权限 |
| DBA（operator） | 日常运维 TiDB 的一线工程师 | 接管、采集、巡检、TiDB 用户与会话管理、参数调整 |
| 只读观察者（viewer） | 业务负责人、研发负责人、审计人员 | 只读查看集群、巡检报告、任务进展，无任何变更 |

### 典型场景

**平台管理员（admin）**
1. 首次部署后初始化管理员，创建 3 个 DBA 账号与 2 个只读账号并分配角色。
2. 接手一批既有集群，统一录入 TiUP 与数据库凭据；大促前把采集周期从 5 分钟调至 1 分钟。
3. 季度检查时导出审计日志，核对近一个月的参数变更与 Kill 会话记录。

**DBA（operator）**
1. 新集群交付：用「接管集群」录入地址、测试连通性，提交后等采集完成，在拓扑图确认组件齐全。
2. 业务反馈 SQL 卡住：从总览 → 集群 → 会话管理定位长事务并 Kill，回任务中心确认成功。
3. 早上例行巡检：对全部集群一键巡检，查看分级结果，下载「严重」项报告发到群里。

**只读观察者（viewer）**
1. 大促前打开总览，确认纳管集群数与异常集群数均符合预期。
2. 查看某业务集群的实例状态与性能趋势，不做任何操作。
3. 从历史报告中下载上次的 HTML 巡检报告留档。

### 5.5 TiDB 用户管理（F-33 ~ F-44，均在集群视角内）

| 编号 | 功能名 | 功能描述 | 优先级 | 验收要点 |

## 7. 页面清单与 UI 设计说明

### 7.1 视觉风格

- **定位**：企业级管理台，信息密度优先，克制不用花哨动效。

### 8.1 接管校验规则

| 规则编号 | 规则 | 失败处理 |
| --- | --- | --- |
| R-01 | 集群名必填且全局唯一（不区分大小写） | 前端即时校验 + 后端唯一索引兜底 |
| R-02 | TiUP IP 支持 IPv4 / 域名；端口默认 22，必填 | 格式不合法拒绝提交 |
| R-03 | SSH 校验必须通过（登录成功 + 能读取 TiUP 部署目录） | 阻止提交，提示检查账号权限与 sudo 配置 |
| R-04 | 数据库连通性校验必须通过（成功执行一次轻量 `SELECT 1`） | 阻止提交，区分「网络不通 / 认证失败 / 端口错误」 |
| R-05 | PD API 探测为**建议项**：失败不阻止提交，但采集时该部分数据标记为「未采集到」 | 详情页对应字段显示「—」并标注原因 |
| R-05a | PD 地址不需要用户填写：表单留空时由服务端自动识别（TiUP 元数据 `pd_servers` → `information_schema.cluster_info`），识别失败不阻断接管；采集到 PD 实例后会回填该字段 | 表单 PD 项显示「留空自动识别」；接管后详情页能看到 PD 地址 |
| R-06 | 单次连接测试整体超时 15s，单项超时 5s | 超时项标红并给出超时提示 |
| R-07 | 提交后立即创建异步采集任务，前端跳转任务详情 | 采集失败不影响纳管记录存在，标记为降级 |

### 8.2 采集失败降级策略（三级状态机）

| 状态 | 触发条件 | 平台表现 |
| --- | --- | --- |
| 正常（Healthy） | 最近一次采集全部成功 | 数据实时展示，无标记 |
| 降级（Degraded） | 部分采集项失败，或最近一次失败但此前有成功数据 | 展示上次成功快照 + 「数据截至 HH:mm:ss」标记 + 失败项清单 + 重试按钮 |
| 异常（Error） | 连续 3 次采集失败，或从未采集成功 | 列表状态列红色「异常」；详情页保留最后一次快照（若有）并置顶告警条 |

补充规则：采集失败**不影响**列表可访问性与巡检入口可用性；降级/异常计入总览「异常集群数」；同一集群并发刷新复用进行中任务；所有展示数据携带 `fetched_at` 时间戳（Tooltip 展示）。

### 8.3 巡检项分级规则

| 分级 | 判定含义 | 展示 | 计入通过率 |
| --- | --- | --- | --- |
| 严重（Critical） | 不满足预期且存在明确风险（如 root 未设密码、TiKV 单副本、磁盘剩余 < 10%） | 红色，默认展开 | 计入分母，不计入分子 |
| 警告（Warning） | 不满足最佳实践但暂无直接故障风险（如未开启慢日志、连接数接近上限） | 黄色 | 计入分母，不计入分子 |
| 通过（Pass） | 满足预期 | 绿色 | 计入分母与分子 |
| 不适用（N/A） | 当前版本/部署模式不支持此项（如 v6.5 无 Resource Group 检查） | 灰色 | **不计入分母** |
| 未知（Unknown） | 采集缺失或检查执行异常，无法判定 | 灰色 + 原因 | **不计入分母** |

- 通过率 = 通过项 /（严重 + 警告 + 通过），保留一位小数。
- 报告整体结论：存在严重项 → 「不通过」；仅警告项 → 「有风险」；否则 → 「通过」。
- 巡检项执行顺序无关，单项失败不中断整份巡检。

## 9. 非功能需求

### 9.1 性能

| 指标 | 要求 |
| --- | --- |
| 列表类接口响应（集群/主机/实例/任务/用户，≤ 1000 条分页） | P95 < 1s |
| 单集群完整采集耗时 | < 10s（含 SSH + DB + PD 三路并行） |
| 拓扑图渲染 | 100 节点内首屏 < 1s，拖拽缩放帧率 ≥ 30fps |
| 巡检单集群执行 | < 30s（20 项） |
| 并发接管/采集 | 默认并发 4，可配置；超出排队不失败 |
| 页面首屏（生产构建，4G 内存浏览器） | < 2s |

### 9.2 安全

| 项 | 要求 |
| --- | --- |
| 凭据存储 | OS 密码与 DB 密码加密存储（对称加密，密钥不进代码库），接口一律不返回明文，展示掩码 |
| 传输 | 全站 HTTPS 部署（反代终止），前端不落盘敏感信息 |
| 认证 | JWT，含过期与签发时间；支持主动失效（禁用用户/改密） |
| 密码策略 | 平台账号 ≥ 8 位含字母与数字；首次登录建议强制改密（见待确认） |
| 注入防护 | 所有 SQL 参数化；TiDB 用户名/库名等标识符做白名单校验 |
| 审计 | 8.4 表中所有写操作必留审计；审计日志不可修改删除 |
| 敏感操作 | 移除纳管、Kill 会话、改全局变量、删 TiDB 用户、切换演示模式均需二次确认 |

### 9.3 可用性

- 单二进制启动即可用，不依赖外部中间件；元数据库自动建表与迁移。
- 采集失败不阻塞任何页面；接口失败给出可重试提示，不出现空白页。
- 演示模式下全部页面与流程可完整走通（含写操作的 mock 响应）。
- 目标可用性：平台自身 99.5%。

### 9.4 可观测性

- 暴露健康检查端点与基础运行指标（采集成功率、任务队列长度、接口耗时）。
- 任务失败必须落库并保留错误摘要，可在任务详情追溯。
- 关键操作与异常写结构化日志，含 request_id 便于串联。
